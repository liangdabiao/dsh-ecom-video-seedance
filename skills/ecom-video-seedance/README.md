# Ecom Video → Seedance Prompt（agent 原生 · 零密钥）

> 你刷到一条带货爆款视频，想让 AI 照着再来一条——本 skill 就是那个"翻译官"：
> 它把视频**看懂**（拆成一张张镜头卡片），再把卡片**翻译**成即梦（Seedance）
> 能直接执行的提示词。你拿到手的，是一套可以直接粘贴进即梦的完整提示词包。

**不需要任何 API key。** 抽帧切镜交给 ffmpeg 脚本（确定性活），看帧拆解与提示词编导由
**agent 自己的视觉能力**完成，最后用脚本做硬校验 + 渲染成 md/HTML。

**它能回答三个问题：**

1. 这条视频是**怎么拍出来的**？（镜头怎么切、光怎么打、动作怎么排、卖点怎么放）
2. 我要**复刻它**，提示词该**怎么写**？（每镜头一条 + 整片一条 + 负面词 + 参考图清单）
3. 我想**改风格**（自然流种草 / 千川付费流），提示词要**怎么变**？

---

## 一、它是怎么想问题的：先把"感觉"变成"参数"

参考的 6 篇「点金手丰年」实战方法论文档反复讲一个核心观点：

> 你写"拍一个好看的视频"，AI 给你一坨废片；你写"25 岁亚洲女性，黑色齐肩长发，
> 缓慢转身，嘴角微微上扬，暖光侧逆光，中景缓慢推镜，4K 高清，面部不变形"——
> 一次出片。**差距不在模型，在提示词。**

方法论把一条好提示词拆成了五个必填项，叫 **S-A-C-S-C**：

| 要素 | 通俗解释 | 例子（头发护理广告） |
|---|---|---|
| **S**ubject 主体 | 画面里是谁/是什么产品，长什么样 | "两位深棕肤色女性，黑色长直发，深灰/米白运动背心" |
| **A**ction 动作 | 在做什么，**按时间顺序一步步写** | "双手伸入→分开头发→向下滑动→滑至发尾" |
| **C**ontext 场景 | 在哪里，光怎么打，有什么细节 | "美发沙龙，镜前柔光侧逆光" |
| **S**hot 镜头 | 景别/视角/景深/运镜 | "特写，平视，浅景深，固定镜头" |
| **C**olor 情绪 | 色调/饱和度/对比度 | "冷色调，高饱和，对比适中" |

五项缺一个，AI 就在那个维度"自由发挥"——而 AI 的自由发挥通常就是翻车现场
（六根手指、脸崩、头发粘成一块）。

**本 skill 做的事，就是把这套"人肉拆解"变成 agent 可执行的流程**：脚本把帧抽出来切好镜，
agent 直接读帧写拆解卡，校验器卡住字数和字段，最后渲染成可逐镜对照的 HTML。

## 二、分工：脚本做确定性的事，agent 做判断的事

```
带货视频
   │ ① analyze.py（几秒，不联网）：ffprobe 元信息 + 1fps 抽帧
   │    + ffmpeg 场景切换检测 + 镜头切分 + 每镜关键帧绝对路径清单
   ▼
manifest.json + frames/            ← 素材备好，等你（agent）看
   │ ② agent：read_image 逐镜读关键帧（一次并发 6-8 张），跨镜比对动作/光位/卷度
   │    按 S-A-C-S-C 写两张 JSON
   ▼
storyboard.json（拆解卡）+ payload_<style>.json（提示词包）
   │ ③ replicate.py（不联网）：硬校验（≤200字/镜、≤800字整段、字段齐全、镜头对齐）
   │    + 渲染
   ▼
<视频名>_<风格>_提示词.md / .html   ← 每镜提示词旁就是原片关键帧，逐镜对照
   │ ④ seedance_storyboard action=save
   ▼
侧栏工作台（我的分镜 / 生成历史 / 每存一版都留记录）
```

**为什么不让脚本调视觉模型？**

| | 脚本调外部视觉 API（旧版） | agent 直接读帧（现在） |
|---|---|---|
| 密钥 | 要 `DEEPSEEK_API_KEY`，401/限流就卡死 | 零密钥，不联网 |
| 上下文 | 每镜单独发，看不到前后关系 | 帧都在同一上下文，可跨镜比对 |
| 成本 | 每版按调用计费 | 零 API 成本 |
| 失败点 | 网络 + 额度 + 解析 + 渲染 四层 | 只剩脚本本身（纯本地） |

## 三、镜头卡长什么样

（下面是 jimeng 广告镜头 B 的真实拆解，一字未改）

```json
{"shot_type": "特写",
 "angle": "平视，从人物背后拍摄，聚焦于头发",
 "camera_move": "固定镜头",
 "lighting": "冷光柔光，顶光，头发有明显高光",
 "color": "冷色调，高饱和，对比适中",
 "subject_person": "女性，肤色偏深，深灰色运动背心，背对镜头，黑长直发顺滑有光泽",
 "action_steps": ["人物背对镜头，双手从两侧伸入画面，手指分开头发",
                  "手指从头发中段向下滑动，展示顺滑和光泽",
                  "手指继续向下移动，头发在手指间流畅滑过"],
 "interaction": "手指与头发接触，轻轻分开并向下滑动，头发顺滑无打结",
 "onscreen_text": "左上角有 AI生成 水印",
 "selling_point": "头发的顺滑、光泽和健康",
 "purpose": "卖点展示"}
```

注意这些细节：**动作被拆成了带箭头的时序链**（方法论要求"写慢、写连续、写过程"）、
**表情用物理描述**、**水印被如实记录**（生成时作为"不可复刻元素"排除）。

## 四、快速上手

```bash
# 前置：ffmpeg/ffprobe 在 PATH；Python 3.8+（只用标准库，不用 pip 装东西）
# 不需要 API key

# 0. 把技能复制到工作区（插件环境下 bash 读不到插件安装目录）
cp -r "<技能目录>" ./seedance-skill

# 1. 感知准备（几秒）
python scripts/analyze.py "爆款视频.mp4"

# 2. agent：按打印的帧路径 read_image 读帧，写 storyboard.json + payload_faithful.json
#    （可先要骨架）
python scripts/replicate.py "爆款视频.mp4" --scaffold --style faithful

# 3. 校验 + 渲染（不通过就改 JSON 重跑）
python scripts/replicate.py "爆款视频.mp4" --payload payload_faithful.json --style faithful --duration 15

# 4. 只想校验、先不渲染
python scripts/replicate.py "爆款视频.mp4" --payload payload_paid.json --check
```

**参数速查**

| 参数 | 取值 | 说明 |
|---|---|---|
| `--style` | `faithful`（默认）/ `organic` / `paid` | 忠实复刻 / 自然流种草 / 付费流转化 |
| `--duration` | 4-15，默认 15 | 目标成片时长：校验时间锚点合计、写进 HTML 页头 |
| `--payload` | 路径 | 提示词包 JSON（缺省找 `payload_<style>.json` / `payload.json`） |
| `--shot` | 如 `A,C` | 只渲染指定镜头（改单镜后重出用） |
| `--check` | 开关 | 只校验不渲染 |
| `--scaffold` | 开关 | 生成提示词包骨架 |
| `--out` | 默认 `seedance-out/` | 产出目录 |

`analyze.py` 侧参数：`--fps auto|2`｜`--min-shot 0.8`｜`--force` 重建｜`--clean` 清缓存｜`--json`。

产出两个文件：`<视频名>_<风格>_提示词.md`（纯文本，方便复制）和
`<视频名>_<风格>_提示词.html`（**双击浏览器打开**：每条镜头提示词旁边就是原片
关键帧，肉眼核对拆解准不准，还标了每镜字数）。

## 五、三种风格有什么区别

| | faithful 忠实复刻 | organic 自然流 | paid 付费流 |
|---|---|---|---|
| 目标 | 最大程度还原原片 | 抖音自然流种草出单 | 千川投放强转化 |
| 镜头 | 照原片 | 中景跟拍、平视、贴近日常 | 极致特写、视觉冲击 |
| 光影 | 照原片 | 自然光柔光暖色调 | 硬光侧逆光、电影级 |
| 叙事 | 照原片 | 痛点/种草，节奏舒缓 | 奇观钩子、快节奏、行动号召 |
| 会做什么调整 | 只替换不可控元素 | 常会补促单镜头、真实化场景 | 强化钩子、加对比结构 |

## 六、拿到提示词之后怎么用（即梦实操）

1. 按"**@参考图清单**"准备素材：产品图 1-3 张（正面/侧面/细节，自然光+纯色背景
   +抠图锐化）；要用真人脸参考时，照片需打码/抠脸/转手绘风过审
2. 打开即梦网页版 → 视频生成 → **全能参考**模式上传素材
3. 粘贴"**完整版提示词**" + 基础参数段；英文负面词贴到负向栏
4. 场景简单（≤2 分镜）可先用 **Seedance 2.0 fast** 省积分
5. 效果不对 → 用"单变量修改法"：只改一处（某个镜头、某个光影、某件道具）再重出
6. 建议 720P 出小样验证逻辑，再上 1080P 成片（省一半积分）

## 八、成本账

| 操作 | 耗时 | 成本 |
|---|---|---|
| 感知准备 analyze（15s 竖屏视频） | 2-4 秒 | 0（纯本地 ffmpeg） |
| 读帧拆解 + 写提示词（agent） | 一次对话轮次内完成 | 走你的对话额度，无额外 API |
| 校验 + 渲染 | < 1 秒 | 0 |
| 换风格/改单镜 | 只改 JSON 重跑，秒级 | 0 |

一份视频的感知结果永久缓存，改文案不会重抽帧。

## 九、常见问题

**Q：为什么不把视频直接丢给模型要提示词？**
一次调用做不到两件事：既要逐镜头看清楚（每镜头单独关键帧），又要按编导规则约束输出。
分两步还有个好处——中间产物分镜表可以人工检查纠错，生成可以局部重跑（只改一镜），
而不是每次全凭运气。

**Q：为什么不让脚本调视觉模型，而是 agent 自己读帧？**
帧进 agent 自己的上下文，能跨镜比对（同一只手、同一束光、同一缕卷度），外部 API 每次
只看一小段看不到前后关系；而且零密钥、零额度、不怕 401 和限流。

**Q：提示词里的品牌名/产品外观靠谱吗？**
模型只能从画面猜产品。把真实信息（品牌、卖点、色号）写进 `payload` 的
`replication_strategy` / 镜头提示词；具体外观用 `@产品参考图` 占位 + "1:1 还原"约束，
不要指望文字描述还原品牌 LOGO——`fidelity_notes` 会明确列出哪些元素不可控。

**Q：口播文案是原片原话吗？**
不是。本技能只读画面、不分析音轨，口播内容是从字幕和画面推断的（产出中已标注）。
准确口播建议自己补：15 秒视频配 120 字左右，正好符合方法论的最佳字数。

**Q：能处理多长的视频？**
抽帧按 1fps（>2 分钟自动降 0.5fps）；镜头多时你读帧的轮次会变多。几分钟的视频建议
先切出要复刻的片段，拆解质量更高。

**Q：校验没过怎么办？**
按报错改 `payload_<style>.json`（或 `storyboard.json`）后重跑，别绕过校验，也别手改渲染产物。
`--check` 可以先只跑校验看还有几项问题。

## 十、已知局限

- **无音频分析**：口播/BGM 只能从画面推断
- 剧烈动作、多人复杂交互的视频：拆解照常，但生成会按编导规则主动降速降复杂度
  （这是刻意为之——方法论实测这类元素极易翻车，稳定优先）
- 画面小字（<20px）识别不可靠，只作辅助线索
- 非带货类视频也能拆解生成，但"钩子/促单"等带货字段的建议参考意义有限
- 抽帧是 1fps，镜头内部更快的动作细节可能只捕到两三帧；需要细看可用 `--fps 2`
